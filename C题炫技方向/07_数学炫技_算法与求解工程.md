# 07 炫技｜算法与求解工程：把"我算了"变成"我证明了它是最优的"

> **审计裁定（14）**：S = M-34；A = M-33；B = M-36；C = M-32/35；D = M-31。只保留最优性证书 + 交叉对拍；Benders 明确不做，规模表/热启动进附录。

> 本题**全部可精确求解**（LP；即使加逻辑约束也只需 MILP），因此算法层面的炫技方向**不是"用更炫的算法"，
> 而是"把精确求解做到工程级严谨，并给出最优性证书"**。
>
> 本文件的所有建议都以一个前提为准：**能用精确方法就不要用启发式。**
> 元启发式在本题中不但是负担，而且是**减分项**——因为它放弃了本题最大的红利：对偶信息。
>
> 对应总览条目：`M-31`～`M-36`。

## 1. 精确 vs 启发式：本题的分工表

| 任务 | 正确方法 | 禁止的方法 | 理由 |
|---|---|---|---|
| 问题 1 单日调度 | **LP（HiGHS/Gurobi）** | GA / PSO / SA | 凸 LP 可全局最优，秒级求解，且给对偶 |
| 问题 2 两阶段随机 | **LP（场景展开）或 Benders** | 任何元启发式 | 场景展开后仍是 LP |
| 问题 3 多阶段滚动 | **逐次 LP（滚动）或场景树 LP** | 强化学习 / 遗传算法 | 每步都是 LP；RL 无最优性保证且无法解释 |
| 问题 4 波动电价 | **LP + 情景** | 同上 | 同上 |
| 情景缩减 | k-means / 前向选择 | — | 这是唯一的"近似"环节，需报告误差 |
| **若引入电池循环成本（非凸）** | **MILP** 或 **分段线性近似** | 元启发式 | 分段线性化后仍是 LP/MILP |
| **仅作为对照实验** | 允许贪心策略作为基线 B2 | — | 基线是为了证明优化解更好，不是为了求解 |

> **论文里的一句"炫技话术"**：
> "本文的模型为线性规划，凸且可行域为多面体，因此任何可行解的目标值与全局最优值之间
> 可由对偶间隙直接刻画。本文报告的对偶间隙为 {0 或 <1e-9}，
> 因此所报结果为**全局最优**而非局部最优。"
>
> **这一句就把所有"用启发式只报一个数"的论文比下去了。**

## 2. M-31｜Benders / L-shaped 分解：当场景展开太大时（审计 `14`：D 级，不并入正文）

### 2.1 什么时候需要

| 规模 | 做法 |
|---|---|
| 单日 144 时段 × 1 场景 | 直接 LP（毫秒级） |
| 单日 × 100 场景（T=144） | 直接展开 LP（约 $10^4$–$10^5$ 变量，秒级） |
| **全窗 334 天 × 144 时段 × 100 场景** | $4.8\times10^6$ 变量级 → **考虑分解** |
| 问题 3 多阶段 × 多场景 | 场景树指数增长 → **考虑分解或滚动** |

### 2.2 两阶段结构（问题 2 的标准形式）

$$
\min_{x}\ \ c^\top x+\sum_{\omega\in\Omega}\pi_\omega\, Q(x,\omega)
\qquad
Q(x,\omega)=\min_{y_\omega}\ \ q^\top_\omega y_\omega
\ \ \text{s.t.}\ \ Wy_\omega\le h_\omega-T_\omega x
\tag{43}
$$

$Q(x,\omega)$ 是凸的分段线性函数，可用**割平面**近似：

$$
Q(x,\omega)\ \ge\ \alpha_k+\beta_k^\top x
\quad\text{（最优性割）},
\qquad
0\ \ge\ \gamma_k+\delta_k^\top x
\quad\text{（可行性割）}
\tag{44}
$$

### 2.3 算法骨架（L-shaped / 多割）

```
主问题： min c'x + θ
         s.t.  θ ≥ α_k + β_k'x   （已生成的最优性割）
               γ_k + δ_k'x ≤ 0   （已生成的可行性割）
   ↓ 解出 x̂, θ̂
子问题： 对每个 ω 解 Q(x̂,ω)
   ↓ 得到次梯度 β_ω 与目标值
收敛判据： θ̂ ≥ Σ π_ω Q(x̂,ω) - ε ？
   是 → 停止，输出 (x̂, θ̂)
   否 → 生成新割，回到主问题
```

### 2.4 论文里必须报告的内容

| 项目 | 说明 |
|---|---|
| 迭代次数 | 收敛用了多少轮 |
| 下界与上界的收敛曲线 | **画出来**（这是分解法的"炫技图"） |
| 最终 gap | 应 < 1e-6（相对） |
| 与直接展开 LP 的对照 | **最优值必须一致**（这是最有力的正确性证据） |
| 加速比 | 分解 vs 直接展开的求解时间 |

> ⚠️ **警告**：Benders 实现容易出错（符号、对偶、可行性割）。
> **只有在直接展开 LP 确实超出内存/时间预算时才做。**
> 若直接展开能解，就**直接用，并在论文里说明"该规模在商用 LP 求解器上可直接精确求解，
> 无需分解"**——这同样是专业的判断（**知道什么时候不需要技巧，本身就是水平**）。

### 2.5 一个更实际的替代：按日分解 + 状态衔接

本题的天然结构是**天与天之间只通过日末 SOC 耦合**。因此可以：

$$
\min_{\{S^{end}_d\}}\ \sum_{d=1}^{D} C_d\big(S^{start}_d\big)
\qquad\text{s.t.}\qquad
S^{end}_d=S^{start}_{d+1}
\tag{45}
$$

- **外层**：对 $S^{start}_d$ 搜索（由于 $C_d$ 凸，可用**次梯度法 / 割平面**，梯度来自日 LP 的对偶）；
- **内层**：每天一个独立 LP（$T=144$，毫秒级），**可完全并行**。

> **这个结构的价值**：它把"全窗 1 个大 LP"变成"334 个小 LP + 一个一维/低维割平面外层"，
> 既保留了全局最优性（因为 $C_d$ 凸），又天然并行、天然给出跨日水价值。
> **并且它与 `02` §1 的对偶语言完全一致**——外层乘子就是日末 SOC 的水价值。
>
> **强烈推荐这条路线**，它比 Benders 更贴合本题结构，实现风险更低。

## 3. M-32｜滚动热启动：问题 3 的工程优化（审计 `14`：C 级，仅附录/代码）

问题 3 每天 4 次滚动求解，全窗 334 天 = **1336 次 LP**。若每次冷启动，可能有明显开销。

```python
# 滚动热启动：用上一次的解作为下一次的初值/基
prev_sol = None
for d in days:
    for m in [0, 6, 12, 18]:
        prob = build_rolling_lp(d, m)
        if prev_sol is not None:
            prob.set_warm_start(prev_sol)   # HiGHS/Gurobi 支持 basis 或 primal start
        sol = prob.solve()
        prev_sol = sol
        record(sol)
```

**报告方式**：

| 组 | 冷启动总耗时 | 热启动总耗时 | 加速比 | 最优值是否一致 |
|---|---:|---:|---:|---|
| 全窗 1336 次 LP | {…} s | {…} s | {…}× | **必须一致** |

> ⚠️ **前提**：热启动**不得改变最优值**。必须断言两次求解的目标值差 < 1e-6。
> 若不一致（例如热启动导致提前终止），说明容差设置有问题，**这本身就是一处必须报告的发现**。

## 4. M-33｜交叉求解器对拍：最低成本的强证据

**做法**：用**两个独立的求解器/建模方式**求同一个问题，比较最优值。

| 对拍方式 | 说明 | 强度 |
|---|---|---|
| 换求解器 | HiGHS `highs-ds` vs `highs-ipm`（对偶单纯形 vs 内点） | ★★☆ |
| 换开源/商业 | HiGHS vs Gurobi vs CBC | ★★★ |
| **换模型形式** | 显式 SOC 变量 vs 消去 SOC（用累计和表达） | ★★★★ |
| **换建模工具** | 手写矩阵 vs PuLP/linopy/Pyomo | ★★★ |
| **换方法族** | LP 最优 vs 离散 DP 收敛值 | ★★★★ |

> **最强的是"换模型形式"和"换方法族"**：
> 前者证明你不会因为建模笔误而得到巧合的正确结果；
> 后者（如 DP 从上方收敛到 LP 最优值）是**完全独立的方法论验证**。

**论文写法**：
> "为排除建模与求解器层面的实现错误，本文用两种独立的模型形式
> （显式 SOC 递推 与 SOC 消去的累计和形式）分别求解，
> 最优值一致到 6 位小数（{…} 元 vs {…} 元）；
> 并用离散动态规划（{N} 个 SOC 节点）从上方收敛至 {…} 元，
> 与 LP 最优值的相对差为 {…}%，印证了 LP 解的全局最优性。"

## 5. M-34｜最优性证书：三联报告

每次求解后必须同时检查并报告：

| # | 指标 | 合格标准 | 检查方式 |
|---|---|---|---|
| 1 | **求解器状态** | `optimal`（不是 `optimal_inaccurate` / `time_limit`） | 读状态码 |
| 2 | **原始可行性残差** | $\max_t\lvert\text{balance}_t\rvert\le10^{-6}$ kWh；$S_t\in[\underline S,\overline S]$ | **独立**重算，不复用求解器输出 |
| 3 | **对偶可行性 / 间隙** | 相对 gap $\le10^{-9}$ | 读求解器 gap 或自算 |
| 4 | **KKT 互补松弛** | 阈值律违反次数 = 0（见 `02` §3.4） | 断言 |
| 5 | **费用复算** | 用**独立代码**从调度表重算费用，与目标值一致 | 另写一段审计函数 |
| 6 | **单位一致性** | 所有电量 = 功率 × $\Delta t$；费用单位元 | 断言 + 量纲检查 |

> **第 5 条是"防自欺"的关键**：不要用优化器的目标值当作你的费用结果，
> 而是**从输出的调度表重新计算一遍**。两者一致才说明约束写对了。
> 这个做法在 `C题验证方案/04` 中称为"独立审计"。

**论文里的一句话**：
> "所有结果均通过了原始可行性（残差 ≤ 1e-9 kWh）、对偶最优性（相对间隙 ≤ 1e-9）
> 与费用独立复算（与目标值偏差 < 1e-6 元）三重检验。"

## 7. M-36｜敏感性分析的实验设计化（审计 `14`：B 级，条件并入）

多数队伍的灵敏度是"手改一个参数跑一遍"。升级方案有三档：

| 档 | 方法 | 说明 | 耗时 |
|---|---|---|---|
| 低 | **单参数扫描** + 龙卷风图 | 常规做法，必做 | 1 h |
| 中 | **拉丁超立方（LHS）** | 多参数同时扰动，样本效率远高于网格 | 1 h |
| **高** | **Sobol 全局敏感性指数** | 分解每个参数对输出方差的贡献（含交互项） | 2.5 h |

### 7.1 Sobol 指数的含义（可直接写进论文）

$$
S_i=\frac{\mathrm{Var}_{x_i}\big(\mathbb{E}[Y\mid x_i]\big)}{\mathrm{Var}(Y)},
\qquad
S_{ij}=\frac{\mathrm{Var}_{x_{ij}}\big(\mathbb{E}[Y\mid x_{ij}]\big)}{\mathrm{Var}(Y)}-S_i-S_j
\tag{47}
$$

**$S_i$ 大 = 该参数单独决定结论；$S_{ij}$ 大 = 该参数只有与其他参数**联合**才影响结论。**

**报告方式**（一张柱状图 + 一张表）：

| 参数 | 基准值 | 范围 | 一阶指数 $S_i$ | 总效应 $S_{Ti}$ | 排名 |
|---|---|---:|---:|---:|---:|
| 充放电效率 $\eta$ | 0.9 | 0.85–0.95 | {…} | {…} | {…} |
| 储能容量 $\overline S$ | 12000 | 9600–14400 | {…} | {…} | {…} |
| 紧急购电倍数 $k$ | 5 | 2–10 | {…} | {…} | {…} |
| 光伏预报误差 | 实测 | ×0.5–×2 | {…} | {…} | {…} |
| 电价水平 | 附件 4 | ±20% | {…} | {…} | {…} |

**结论模板**：
> "全局敏感性分析表明，总费用对 {参数 A} 最敏感（$S_i=${…}），
> 且 {参数 B} 与 {参数 C} 存在显著交互效应（$S_{ij}=${…}）。
> 这意味着 {现实含义：例如'效率与容量必须同时改进才有意义'}。
> 相比之下，本文结论对 {参数 D} 不敏感（$S_{Ti}<$ {…}），
> 因此 {该参数的缺失/不确定性} 不影响本文主要结论。"

> ⚠️ **绝对不要写的**：把所有参数做完 Sobol 后写"所有参数都重要，说明模型很敏感"。
> **敏感性分析的目的是找出"哪个参数决定了结论"**，不是证明模型脆弱。
> **若所有参数都不敏感，那也是一个有价值的结论**（"结论稳健"）。

### 7.2 龙卷风图的正确写法

横轴 = 输出（总费用），中心竖线 = 基准值，每根条 = 一个参数在 $[\text{下限},\text{上限}]$ 内变动时的输出范围。
**按条长排序**，并在图上标注**"结论是否反转"的阈值在哪里**。

> **关键**：不仅要画范围，还要标出**结论反转点**。
> 例如"若紧急购电倍数 $k$ 降至 {…} 以下，'留安全边际'的建议不再成立"。
> **这才是灵敏度分析应有的产出。**

## 8. 求解工程的完整检查流程（可直接做成函数）

```python
def solve_and_certify(prob, tol=1e-6, name=""):
    """求解 + 六项证书检查；任一项失败即抛异常，绝不静默通过"""
    sol = prob.solve()

    # 1. 求解器状态
    assert sol.status == "optimal", f"[{name}] 非最优状态: {sol.status}"

    # 2. 原始可行性（独立重算，不复用求解器内部量）
    balance_res = recompute_balance_residual(sol)        # 用原始载荷/光伏/电价重算
    assert abs(balance_res).max() <= tol, f"[{name}] 平衡残差过大: {abs(balance_res).max()}"

    soc = recompute_soc(sol)
    assert soc.min() >= 1200 - tol, f"[{name}] SOC 越下界: {soc.min()}"
    assert soc.max() <= 10800 + tol, f"[{name}] SOC 越上界: {soc.max()}"

    # 3. 互斥性（见 02 §5）
    assert (sol.charge * sol.discharge <= tol).all(), f"[{name}] 出现同时充放电"

    # 4. 阈值律一致性（见 02 §3.4）
    viol = count_threshold_violations(sol, tol)
    assert viol == 0, f"[{name}] 阈值律违反 {viol} 次"

    # 5. 费用独立复算（关键：不信任求解器目标值）
    cost_indep = recompute_cost_from_schedule(sol)
    assert abs(cost_indep - sol.objective) <= 1e-6, \
        f"[{name}] 费用复算不一致: {cost_indep} vs {sol.objective}"

    # 6. 对偶间隙
    gap = abs(sol.objective - sol.dual_objective) / max(abs(sol.objective), 1)
    assert gap <= 1e-9, f"[{name}] 相对对偶间隙过大: {gap}"

    return sol, dict(residual=abs(balance_res).max(), gap=gap, cost=cost_indep)
```

> **把这 6 条写进论文的"模型检验"小节**（一句话带过即可），
> 并在**附录**里贴这个函数。评审看到"独立性复算 + 阈值律断言"，
> 就知道你的结果是可信的——**这是"验证即炫技"的核心。**
