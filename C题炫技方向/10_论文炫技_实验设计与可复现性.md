## 1. 消融实验矩阵：创新五段式的证据引擎

### 1.1 消融的三种类型（都要做，作用不同）

| 类型 | 做什么 | 回答的问题 |
|---|---|---|
| **删减消融**（leave-one-out） | 从完整模型逐个移除模块 | "这个模块有用吗？" |
| **替换消融**（substitution） | 把模块换成更简单的版本 | "更复杂是必要的吗？" |
| **添加消融**（add-one-in） | 从基线逐个添加模块 | "每条改进贡献多少？" |

> **推荐做"添加消融"作为主线**（从最简基线出发逐步加），因为它**天然讲了一个递进的故事**，
> 而且能直接生成一张"改进路径"表——比"删减"更易读，也更像"我一步步把问题解决了"。

### 1.2 本题的完整消融矩阵

**基线定义（从最简到完整的八层基线 B0–B7，另设 M 风险层）**：

| 层级 | 模型配置 | 新增模块 |
|---|---|---|
| **B0** | 无储能：全部净负荷按价购电 | — （闭式，$C^{base}$） |
| **B1** | + 储能，但贪心策略（低于阈值充满/高于阈值放空） | 储能（无优化） |
| **B2** | + 储能，**每日 $S(0{:}00)=S(24{:}00)$ 的日环状 LP（逐日独立）** | 精确优化，但无跨日 |
| **B3** | + 跨日 SOC 连续递推 | 跨日状态 |
| **B4** | + 弃光变量 | 可行性保障（**问题 2–4**；问题 1 典型日最优弃光 = 0） |
| **B5** | + 终端水价值（替代硬边界） | 防短视 |
| **B6** | + 不确定性（场景 + 两阶段） | 随机优化 |
| **B7** | + 多阶段滚动 + 非预期性 | 信息结构 |
| **M（完整）** | + 波动电价 + 联合情景 + 风险度量 | 风险决策 |

**产出表（这张表进论文，是"创新五段式"的统一证据）**：

| 层级 | 总费用（万元，**2025-02-01…12-31 同一窗口**） | 相对 B0 | 紧急购电（kWh） | 弃光（kWh） | 违约费（元） | 求解时间（s） | 边际贡献 |
|---|---:|---:|---:|---:|---:|---:|---:|
| B0 | 1 640.7（固定价）/ 1 702.7（波动价） | — | — | — | — | 0.01 | — |
| B1 | {…} | −{x}% | {…} | {…} | {…} | 0.1 | −{Δ₁}% |
| B2 | {…} | −{x}% | {…} | {…} | {…} | {…} | −{Δ₂}% |
| B3 | {…} | {…} | {…} | {…} | {…} | {…} | {…} |
| … | … | … | … | … | … | … | … |
| **M** | {…} | −{x}% | {…} | {…} | {…} | {…} | −{Δ₈}% |

> ⚠️ **口径统一（否则全表不可比）**：本表所有"总费用"都在**同一个窗口 2025-02-01…12-31（334 天）**上给值。
> B0 = **1 640.7 万元（固定价口径，附件 1 电价）/ 1 702.7 万元（波动价口径，附件 4）**，
> 底数与"相对 B0"必须**同一口径**，不得混用。
> **问题 1 的典型日（全年平均日）结果单列**（$C^{base}=48\ 052.05$ 元、最优 $35\ 126.95$ 元），
> 不进入本表的"相对 B0"——典型日基线 48 052.05 元与窗口基线 1 640.7 万元**相差 341 倍**，
> 混排一次全表就废了。

> **⭐ 关键要求**：**总费用必须沿阶梯 B0→B7/M 单调不增**（每一步只加模块、不减模块）；
> **"边际贡献"列据实报告即可，通常递减**——本题 **B4（弃光变量）的边际贡献恰为 0**
> （典型日允许/禁止弃光同值 35 126.95 元），这属于正常且必须写入。
> 如果某一层加进去**几乎没有改善**（如 <0.5%），
> **那就诚实地写"该模块贡献有限，其主要价值在于保证可行性/提供解释，而非降低费用"**——
> **主动承认一个模块的收益有限，比硬吹它有用可信得多。**
> 而且这正好是"代价—边界"那两段的素材。

### 1.3 消融实验的公平性三条铁律

| # | 铁律 | 违反的例子 |
|---|---|---|
| 1 | **同一场景集 / 同一实际轨迹** | 各模型用各自生成的情景，费用不可比 |
| 2 | **同一指标定义与同一口径** | 一个模型的费用含紧急购电、另一个不含 |
| 3 | **同一预算（时间/内存）** | 给复杂模型更多迭代时间 |

> ⚠️ **第 1 条最常被违反**。正确做法：
> **先在完整模型上生成/固定情景集 $\Omega$（并保存到文件），
> 所有消融变体都读同一份 $\Omega$。** 这样费用差异只反映模型结构，不反映随机性。
> **把 $\Omega$ 存成 `.npz` 并在附录说明——这本身就是可复现性的加分项。**

## 2. 预注册验证协议：避免"看到结果再挑指标"

### 2.1 问题

如果先跑模型、看到结果、再决定"用哪个指标比较"或"选哪个超参数"，
就会产生**选择偏差**——你报告的是"最好的那次"，不是"期望的表现"。

### 2.2 做法：在建模前写一份"验证协议"（半页即可）

> **审计裁定（`14`）**：预注册协议是 **B 级条件项**，建议放**附录**；正文只需一句话声明"测试窗口未参与调参"。

```markdown
## 验证协议（建模前锁定，不得事后修改）

### 数据切分
- 结果报告窗口：**2025-02-01 … 2025-12-31（334 天，题面强制，不可选）**
- 拟合/参数选择窗口：2025-01-01 … 2025-06-30（与 `C题验证方案/05` §3.1 一致）
- 未调参验证子窗：**2025-07-01 … 2025-12-31**（**仅用于最终报告，不参与任何调参**）
- 说明：1 月（01-01 … 01-31）**仅用于储能 SOC 递推的热启动预热**，不参与结果报告
- **必须声明的初始状态**：题面只给 2025-01-01 00:00 的 $S=6\ 000$ kWh，
  **2025-02-01 的初始 SOC 全库未定义**；本文明确采用
  {1 月预热递推 / 每天重置 6 000 / 日末延续} 中的 **____**（三选一，写死并写进假设表）。
  该口径的影响可达 **4.4 pp**（日环状 23.74% vs 全窗自由终端 28.15%），**不声明即不可比**

### 评价指标（预先声明，不得替换）
- 主指标：总购电费用（元），口径见 C-01
- 辅指标：紧急购电量（kWh）、弃光电量（kWh）、实际最大单日费用（元）
- 稳定性指标：跨 N 个随机种子的费用标准差

### 超参数与选择规则
- 场景数 N：由"最优值进入 ±0.5% 平稳带"的最小 N 决定（见 03 §3.3）
- CVaR 置信水平 β = 0.95（固定，不扫描）
- 随机种子：{0,1,2,...,19}，共 20 个，报告均值 ± 标准差

### 停止规则
- 若某模块的添加使主指标改善 < 0.5% 且计算时间增加 > 50%，则不纳入最终模型
```

> **写这份协议只要 40 分钟，但它能挡住评审最锋利的一问：**
> **"你怎么知道这个结果不是调出来的？"**
> 你的回答是："**指标与切分在建模前已锁定（见附录 A），测试窗口未参与任何调参。**"
>
> **这是"炫技"里最像科研的一项，而且几乎没有队伍会做。**

### 2.3 如果时间不够，最小版本

至少做到这两条：
1. **留出至少 2 个月的测试窗口**，且**从未用它调参**；
2. **在附录写明"测试窗口未参与模型选择与参数调整"**。

## 3. 随机性与置信区间：不要只报一个数

### 3.1 哪些环节有随机性

| 环节 | 随机来源 | 处理 |
|---|---|---|
| 场景生成（Bootstrap / 抽样） | 随机种子 | **≥20 个种子** |
| 场景缩减（k-means 初始化） | 初始化 | 同上，或固定种子并声明 |
| 元启发式（若用了） | 种群/初值 | 多重启，报告均值±std 与最好/最差 |
| 误差分布拟合 | 样本 | Bootstrap 置信区间 |

### 3.2 报告格式（必须含区间）

| 指标 | 均值 | 标准差 | 95% 置信区间 | 备注 |
|---|---:|---:|---|---|
| 总费用（元） | {…} | {…} | [{…}, {…}] | 20 个种子 |
| 紧急购电量（kWh） | {…} | {…} | [{…}, {…}] | 同上 |
| 信息价值 VoI（%） | {…} | {…} | [{…}, {…}] | 同上 |

> **审计裁定（`14`）**：多种子/置信区间为 **B 级条件项**；时间不足时至少用"配对差值 + 置信区间"给核心结论，不必把所有指标都做成 20 种子。

> ⚠️ **一个数字 + "约" 是不够的**。
> 报"节省 26.9%"而不给区间，评审无法判断 26.9% 与 27.4% 是否有区别。
> **给出区间，等于告诉评审"我知道自己的精度边界"。**

### 3.3 配对比较优于独立比较

比较两个模型（如"有调整机制"vs"无调整机制"）时，**用同一批种子/同一批情景配对**，
比较**逐对差值**的均值与置信区间，而不是比较两个独立均值。

```python
d = cost_with_adj - cost_without_adj        # 逐种子配对差值
mean_d, se_d = d.mean(), d.std(ddof=1)/np.sqrt(len(d))
ci = (mean_d - 1.96*se_d, mean_d + 1.96*se_d)
print(f"调整机制节省 {mean_d:.1f} 元  95%CI [{ci[0]:.1f}, {ci[1]:.1f}]")
# 若 CI 不含 0，说明改善显著（配对 t 检验的等价结论）
```

> **配对比较的方差远小于独立比较**（因为共同的随机性被抵消），
> 因此**同样的种子数能得到更窄的置信区间**。这是"用更少的计算说更硬的话"。

## 4. 口径锁定：把所有定义放进代码而不是脑子里

### 4.1 问题

同一篇论文里，"购电费"在一节里含紧急购电、在另一节里不含——
**这是最常见的内部不一致，而且往往自己发现不了。**

### 4.2 做法：口径字典 + 单一函数

```python
# config.py —— 全文唯一的口径定义源，论文正文直接引用这里的口径编号
WINDOW   = ("2025-02-01", "2025-12-31")   # 结果窗口：334 天
DT       = 1/6                             # h，10 min
SOC_BOUNDS = (1200.0, 10800.0)            # kWh
SOC_INIT   = 6000.0                        # kWh @ 2025-01-01 00:00
ETA_C, ETA_D = 0.9, 0.9                    # 假设 A2
P_MAX  = 5000.0                            # kW
K_EMERGENCY = 5.0                          # 紧急购电价倍数
K_OVER, K_PENALTY = 1.5, 0.5               # 调整超额 / 违约

def cost_breakdown(schedule, price, load, pv):
    """唯一费用口径函数。论文中所有费用数字都必须由本函数产生。
    返回 dict，键名与论文表头一一对应。"""
    e_plan, e_over, e_pen, e_emg = (schedule[k] for k in
                                    ("E_plan", "E_over", "E_penalty", "E_emergency"))
    return {
        "计划购电费":  float((price * e_plan).sum()),
        "超额费用":    float((K_OVER    * price * e_over).sum()),
        "违约费用":    float((K_PENALTY * price * e_pen ).sum()),
        "紧急购电费":  float((K_EMERGENCY * price * e_emg).sum()),
        "总费用":      float((price*(e_plan + K_OVER*e_over
                                     + K_PENALTY*e_pen + K_EMERGENCY*e_emg)).sum()),
    }
```

> **规则**：论文里出现的任何费用**只能来自 `cost_breakdown`**。
> 若某处需要另一个口径（如不含紧急购电），就**显式调用并单独命名**——
> 绝不在正文里"顺手"手写一个求和式。
>
> **这条规则的价值**：它把"内部不一致"从**语义问题**变成了**代码问题**，而代码可以被检查。

### 4.3 交叉一致性审计（提交前必须跑）

```python
def audit_internal_consistency(paper_numbers: dict):
    """把论文里手填的数字与代码重算的结果对拍。
    paper_numbers 是一个 dict：{指标名: 论文里写的值}"""
    recomputed = recompute_all()
    bad = []
    for k, v in paper_numbers.items():
        # 费用复算判据统一为"相对 ≤1e−4"（对 <1 的量取 1 元作下限，避免除零式退化）
        if abs(recomputed[k] - v) > 1e-4 * max(abs(v), 1.0):
            bad.append((k, v, recomputed[k]))
    if bad:
        raise AssertionError(f"论文与代码不一致：{bad}")
    print("✅ 论文全部关键数字与代码复算一致")
```

> **强烈建议真的把论文里的关键数字录进 `paper_numbers`**（约 30 个数），
> 提交前跑一次。**这能抓住绝大多数"改完代码忘了改论文"的错误。**

> **`run_all.py` 的存在本身就是一种炫技**：它在附录里告诉评审
> "**我们的结果可以在 X 分钟内从原始附件完整重现**"。
> 配合 `random.seed(...)` 与 `code/requirements.txt` 的版本号，可复现性就闭环了。

> ⚠️ **守恒式六项缺一不可**，完整形式为
> $E_t + PV_t\Delta t + P^d_t\Delta t + g_t = L_t\Delta t + P^c_t\Delta t + s_t\Delta t$
> （$g_t$ = 紧急购电量，**只在问题 2–4 出现**；$s_t$ = 弃光电量）。
> **漏掉充电项 $P^c_t\Delta t$ 会让 LP 退化成"既不充电也不放电"的退化解，
> 目标函数直接变成 0.00 元**，而求解器不会报任何错——这是本题最隐蔽的一类错误。
> 反之，**弃光变量 $s_t$ 必须存在**（问题 2–4 的实际日序列 334 天中有 72 天需要）：
> 去掉它那些天直接不可行。但**平均日的最优弃光 = 0**，含/不含弃光变量的平均日最优费用同为 35 126.95 元。
