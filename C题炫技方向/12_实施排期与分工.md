## 一、先立铁律：优先级不可协商

```
P0  五个结果文件正确且合规（result1/2/3/4-2/4-3.xlsx）
        │   不做 → 直接判格式问题，一切免谈
        ▼
P1  四问的核心结论正确（数值可行、量纲正确、跨日衔接正确）
        │   不做 → 评审判决一"读懂题了吗"= 否
        ▼
P2  验证的最低配置（L1 特例单测 + L3 独立审计 + 关键消融）
        │   不做 → 判决二"算对了吗"= 否
        ▼
P3  论文骨架齐备（决策时序图 + 依赖图 + 证据账本 + 口径框 + 假设表）
        │   不做 → 判决三"有想法吗"难拿到
        ▼
P4  套餐 A 数学炫技（分解 + 对偶 + 阈值律 + 相关性尺度拆解）
        │
        ▼
P5  套餐 B（VoI 对照 + 报童 + 最优性证书 + 消融矩阵 + 瀑布图）
        │
        ▼
P6  套餐 C（CVaR 前沿 + Copula + 终端水价值 + 边际价值；鲁棒 M-16 不做）【审计：B 级条件项】
        │
        ▼
P7  锦上添花（机制推广只进 §10.4；Benders/DRO/近似 DP 不做）【审计：C/D 级】
```

> ⚠️ **绝对禁止**：在 P0–P2 未完成时启动 P5 以上任何一项。
> **每往上跳一级，翻车概率增加一档，而一旦 P0 出问题，上面全部归零。**

## 二、按剩余时间选方案

### 方案 α｜剩余 < 8 小时（保命模式）

| 优先 | 做什么 | 耗时 | 交付 |

| 2 | 跑一遍附录代码，确认能运行且与论文数字一致 | 1 h | 零错误 |
| 3 | 独立复算费用（不复用求解器目标值） | 0.5 h | 审计函数通过 |
| 4 | 全文数字一致性核对（摘要=正文=表格=xlsx） | 1 h | 零差异 |

| 6 | **决策时序图 + 问题依赖图** | 1.5 h | 两张图 |
| 7 | **成本分解瀑布图** | 1 h | 一张图 |

**总计约 8 h。全部属于"零风险、高观感"的项。**
**这个方案下不要碰任何模型改动。**

## 三、三人分工（并行不冲突）

### 3.1 角色划分原则

| 角色 | 核心职责 | **不可兼任**的原因 |
|---|---|---|
| **A 建模手** | 模型公式、对偶推导、假设表、创新五段式 | 需要连续思考，最怕被打断 |
| **B 编程手** | 数据管道、求解、结果文件、复现包 | 与 A 频繁对接，但**交付物独立** |
| **C 验证+写作手** | 独立审计、消融、图表、论文结构与排版 | **必须独立于 A/B**，否则审计失效 |

> ⚠️ **审计必须由非实现者执行**。A 或 B 自己"复核"自己的结果，
> 会无意识复现同一个错误（例如同一个符号约定错误会被复制）。
> **C 必须从"输出文件"出发独立重算，而不是读 A/B 的代码逻辑。**
> 详见 `C题验证方案/04_独立审计与非预期性测试.md`。

### 3.2 任务矩阵

| 任务 | A 建模 | B 编程 | C 验证/写作 |
|---|:--:|:--:|:--:|
| 时标对齐与数据核查 | 复核 | **实现** | **独立复算** |
| 四问模型公式 | **主责** | 实现 | 检查单位/方向 |
| 求解与结果文件 | 检查 | **主责** | **回读校验** |
| 对偶/阈值律 | **主责** | 读取对偶 | **一致性断言** |
| 报童推导 | **主责** | 数值对照 | 检查适用边界 |
| VoI 实验设计 | 设计 | **实现** | **独立跑一遍** |
| 消融矩阵 | 设计层级 | **实现** | **核对同场景集** |
| 敏感性分析 | 选参数 | **实现** | 检查是否含"结论反转"判断 |
| 图表 | 定规格 | 出图 | **排版与图注** |
| 论文正文 | 模型章节 | 求解章节 | **结构、摘要、排版** |
| 复现包 | — | **主责** | **从干净环境跑一遍** |
| 提交合规自查 | — | — | **主责** |

### 3.3 交接接口（避免"我以为你做了"）

| 交接点 | 上游交付 | 下游接收标准 |
|---|---|---|
| A→B | 公式、符号表、约束清单 | B 能写出矩阵而无需再问 |
| B→C | `C题代码/result/result*.xlsx` + `C题代码/results_summary.json` | C 能不看代码就复算 |
| C→A | 审计报告（含不一致清单） | A 能定位到具体公式 |
| A/C→论文 | 章节草稿 | 含口径框与证据 ID |

> **强制规则**：**每次交接必须落成文件**（不在聊天里口头交接）。
> 理由：口头交接的信息在 6 小时后会消失，而论文必须与代码一致。

## 四、里程碑与门禁（红黄绿）

### 门禁 G1｜数据与假设锁定（建模开始前）

| 检查 | 通过标准 | 不通过则 |
|---|---|---|
| 时标对齐结论已写入假设节 | 明确"标签=时段末端，144 值对应 144 个区间"，且结果**按位置写入**（第 j+1 格 ← 槽 j） | 🔴 停止建模 |
| 附件 1 身份已核查 | 明确"= 全年逐时段均值，非预报" | 🔴 停止 |
| 信息结构已声明（R1/R2/R3） | 主方案 + 对照方案 | 🔴 停止 |
| 待声明假设表 A1–A8 完成 | 每条含必要性/影响/验证 | 🟡 补齐后再走 |

### 门禁 G2｜四问结果文件合格（每问完成时）

| 检查 | 通过标准 |
|---|---|
| 工作表名、列序、日期范围与模板一致 | 逐格比对 |
| 数值非负、无 NaN、精度统一 | 扫描 |
| SOC 全程 ∈[1200, 10800] | 无越界 |
| 无同时充放电（互斥） | $\min(c_t,d_t)\le 1e{-6}$ kWh |
| 跨日 SOC 连续；问题 1 的 0:00 = 24:00 | 严格相等 |
| 费用独立复算 = 优化目标值 | **相对偏差 ≤1e−4** |
| **`计划购电量`/`调整购电量` 的行列数** | **335 行×147 列**：334 个日期行（2025-02-01…2025-12-31）**已全部预填**，末列标签 `0:00-0:10+1` |
| **`result1` 的 `计划购电量` 版式** | **145 行×2 列**（144 个数据行，**无**"全天购电量/购电费"合计行），末行标签 `0:00+1-0:10+1` |
| **`充放电量` 表体** | **334×6 = 2 004 行**，且**不得保留模板里的字面量 `⁝` 行**（模板 result2/4-2 仅 20 行、result3/4-3 仅 26 行） |
| **`紧急购电量` 逐事件重建** | 模板仅 11 行且含 `⁝` 行；须**按事件逐行**重建，日期 ∈ [2025-02-01, 2025-12-31] |
| **`0:00`/`24:00` 储电量的落格位置** | `0:00` 填在 **`0:00-4:00` 行**、`24:00` 填在 **`4:00-8:00` 行**（**不是最后一行**） |

> ⚠️ **后五项是"照模板改单元格"救不回来的**：`充放电量` 与 `紧急购电量` 模板里
> 只有 2–3 个示例日 + 一个字面量 `⁝` 行，必须**删掉 `⁝` 行、整表重建**。
> 这是最容易被判"格式不合规"直接出局的一处（见 `11` A4）。

### 门禁 G3｜验证最低配置完成（写作开始前）

| 检查 | 通过标准 |
|---|---|
| L1 解析特例单测 | 至少 2 个已知答案的算例通过 |
| L3 独立审计 | 由 C 独立重算，与 B 输出一致 |
| 关键消融 | B0–B5 六层跑通，同场景集 |
| 基线对照 | 无储能 / 贪心 / 完美信息三类基线齐备 |
| 泄漏测试 | 确认计划未使用未来信息 |

### 门禁 G4｜提交前总检（定稿后）

**直接使用 `11` 的避坑清单**（A–E 五组，共 50 条主条目，另含 C1b/C1c/C1d/C10b/C10c 五条子条目，合计 55 行），
配合 `10` §6 的 27 条提交前审计清单，三人各自独立打勾一遍。
两套清单编号不同，**引用时以 `11` 的 A–E 编号为准**（例如"`11` C2 未过"）。

| 状态 | 含义 | 动作 |
|---|---|---|
| 🟢 全部条目通过 | 可提交 | 打包 |
| 🟡 1–3 条不过 | 修正后重检 | 逐条修 |
| 🔴 ≥4 条不过 或 有任一 A 组条目不过 | **停止炫技，全力修 P0/P1** | 必要时砍掉 P5 以上所有内容 |

## 五、时间分配的硬性建议

| 阶段 | 建议占比 | 交付物 |
|---|---:|---|
| 读题 + 数据核查 + 假设锁定 | 12% | G1 通过 |
| 问题 1（模型 + 结果文件） | 12% | `result1.xlsx` + 对偶分析 |
| 问题 2（预报误差 → 两阶段计划 + 报童分位数） | **11%** | `result2.xlsx` + 报童对照 |
| 问题 3（滚动 + VoI） | 18% | `result3.xlsx` + VoI 曲线 |
| 问题 4（波动电价两套结果） | 14% | `result4-2/4-3.xlsx` + 前沿 |
| **结果文件结构校验 + 紧急购电落点分析** | **7%**（由问题 2 让出） | G2 硬检查通过 + 紧急购电落点表 |
| 验证 + 消融 + 敏感性 | 12% | G3 通过 |
| 写作 + 图表 + 合规 + 复现包 | 14% | G4 通过 |

> ⚠️ **问题 2 从 18% 降到 10–12%（本表取 11%）**：题面问题 2 是"每天 0:00 制定一次计划"，
> 不确定性**只有预报误差一条**，场景生成 + 两阶段 + 报童分位数已经够用；
> 再叠加 CVaR / 鲁棒 / 多场景树属于**过度工程**（那是问题 4 的活）。
> 让出的 6–8%（本表取 7%）给两件**必须做**的事：
> ① **结果文件结构校验**（见 G2——判错就是格式问题，一票否决）；
> ② **紧急购电落点分析**：实测最坏 4 h 缺口的起始时次为
> **17 时 144 天、18 时 90 天、16 时 60 天、19 时 40 天，17:00–21:00 合计占 87.4%**。
> 这张落点表既是"读懂题"的证据，也是评审最容易追问的地方。

> ⚠️ **最后一项（写作+合规+复现包）占 14%，且不可压缩。**
> 最常见的失败不是"模型没做完"，而是"模型做完了但论文没合上、附录代码跑不通、结果文件结构错"。
> **请把最后 14% 当作不可挪用的保留时间。**

## 六、"再给我一小时该做什么"决策树

```
剩 1 小时
├─ 结果文件还没校验 → 校验结果文件（P0）
├─ 论文数字与代码不一致 → 跑 audit_internal_consistency（P0）
├─ 附录代码跑不通 → 修代码（P0）
├─ 以上都好，缺图 → 画决策时序图 或 成本瀑布图（P4，最省时的加分）
└─ 以上都好，缺论证 → 写证据账本表（P3，1 小时，逼出所有无证据结论）

剩 3 小时
├─ 缺对偶分析 → 水价值曲线 + 对偶图（P4，性价比最高）
├─ 缺消融 → 消融矩阵 B0–B5（P5）
├─ 缺"是否需要更多预报"的答案 → VoI 四组对照（P5，直接回答题面）
└─ 缺创新证据 → 创新五段式 + 消融（P5）

剩 半天
└─ 方案 β 的第 10–18 项，按序做

剩 一天以上
└─ 方案 γ 的第 19–27 项，但每做一项前先确认 G2/G3 仍为绿
```

## 七、队内沟通的三条纪律

| # | 纪律 | 原因 |
|---|---|---|
| 1 | **任何数字改动都要同时通知三人** | 论文/代码/结果文件三处必须同步，否则出现"论文与代码不符"（可能被取消资格） |
| 2 | **不要说"我觉得差不多"** | 换成"表 x 第 y 行的值是 z，证据在 §w" |
| 3 | **每 2 小时做一次 5 分钟同步** | 只回答三个问题：做到哪了？卡在哪？需要谁帮？ |

> **第 3 条特别有效**：它把"发现方向错了"的时间从半天缩短到 2 小时。
