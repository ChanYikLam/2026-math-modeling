# 00 代码目录与命名规范（唯一权威）

> **本文件是"C 题代码目录格式"的唯一权威定义。**
> 任何文档——包括 `C题*.md` 系列、`论文/*.md`、`论文/sections/*.tex` 附录——
> 提到代码目录、脚本文件名、结果文件路径时，**一律以本文件为准**。
> 发现别处写法与本文件冲突，改别处，不改本文件。
>
> 版本 v1 · 适用：`C题代码/` 工作区与其全部上下游文档

---

## 1. 唯一工作区

仓库根 `2026数学建模正赛/` 之下，**代码只存在于 `C题代码/`**：

- 不得在别处新建代码目录（历史上的 `C_2026/`、`src/`、`submission/`、`appendix/`、`outputs/`、`scripts/` 一律作废）；
- `论文/code` 是指向 `../C题代码/code` 的**软链接**（第 7 节），不是第二份副本；
- 文档目录 `C题知识点解析/`、`C题炫技方向/`、`C题验证方案/`、`C题行业热点与实务/`、`C题写作需求/` 只放说明，**不放代码**。

```text

├── data/                        附件 1–4 只读副本（开发期可直接读仓库内原始附件）
```

### 2.1 例外区：`_坑点复现/`（仓库根，不在工作区内）

`_坑点复现/` 是**既有的、正在使用的**坑点独立复现区（`q1..q4_pitfalls.py`、
`q4_audit.py`、`check_pitfalls.py` 与 `out/` 产出），它按 `C题知识点解析/05_坑点总清单` §9
的要求运行，**暂不迁入工作区**，以避免破坏其相对路径与在跑的结果。约束如下：

- 它是本规范第 1 节"代码只在 `C题代码/`"的**唯一例外**，且**不进 `support.zip`**（属开发支撑，非交付源程序）；
- 其脚本同样必须遵守第 3 节路径解析规则（`__file__` 推导、附件解析顺序），不得使用 CWD 裸路径；
- 若其结论要写进论文，**对应实现必须落到 `code/` 下的正式文件**（如 `audit.py`、`certify.py`、`exp_*.py`）并列入附录 E——
  论文数字不能来自未列入附录的脚本；
- 日后若决定并入工作区，映射为 `C题代码/tests/pitfalls/`（脚本改名 `q<问号>_pitfalls.py`，输出放 `tests/pitfalls/out/`）。

| 目录 | 是否进 `support.zip` | 说明 |
|---|---|---|
| `code/` | 是 | 附录 E 逐字列出其内容 |
| `data/` | 是 | 附件 1–4；打包时从 `CUMCM2026Problems(1)/C题/附件/` 复制 |
| `result/` | 是 | 五个结果文件，工作表名与列序须与 `附件5/` 模板一致 |
| `figures/` | 是 | 论文正文图的矢量版 |
| `intermediate/` | 是 | 固定场景集与审计报告（附录 D） |
| `logs/` `tests/` `notebooks/` `docs/` | 否 | 开发支撑，不随论文提交 |

## 3. 路径解析规则（强制）

文档中同时存在"从仓库根运行"与"从 `C题代码/` 运行"两种用法，因此：

1. **一切路径由 `code/config.py` 用 `__file__` 推导**，禁止使用依赖当前工作目录的裸相对路径（如 `open("附件1.xlsx")`、`"intermediate/x.npz"`）；
2. 仓库根：`ROOT = Path(__file__).resolve().parents[2]`（`code/xxx.py` → `code` → `C题代码` → 仓库根）；
3. 附件目录按顺序解析，命中即止：
   1. 环境变量 `MICROGRID_ATTACH`（便于在别的机器复现）；
   2. `C题代码/data/`（打包后的 `support.zip` 形态）；
   3. `ROOT / "CUMCM2026Problems(1)/C题/附件"`（本仓库开发形态）；
   4. 都不存在则**抛异常并提示三者**，不得静默返回空表；
4. 输出目录同样由 `config.py` 给出单一常量，其他文件一律引用：
   `RESULT_DIR = C题代码/result/`、`FIG_DIR = C题代码/figures/`、
   `INTERMEDIATE_DIR = C题代码/intermediate/`、`LOG_DIR = C题代码/logs/`；
5. `audit.py` 的**独立性只约束"不共用建模费用函数"**：允许从 `config.py` 取路径常量与储能参数，禁止 import 任何建模/费用函数。

## 5. 命名规则

| 类别 | 规则 | 例 |
|---|---|---|
| 模型 | `model_q<问号>.py` | `model_q3.py` |
| 对照/实验 | `exp_<主题>.py` | `exp_voi.py` |
| 绘图 | `plot_` + 图的**文件名**（去 `.pdf`） | `fig06_voi_curve.pdf` → `plot_fig06_voi_curve.py` |
| 开发自检 | `tests/<主题>.py` | `tests/unit_cases.py` |
| 坑点复现 | 例外区 `_坑点复现/q<问号>_pitfalls.py`（见 §2.1） | `_坑点复现/q2_pitfalls.py` |
| 结果文件 | 固定名，不得改名 | `result1.xlsx` … `result4-3.xlsx` |

## 6. 运行方式（两种工作目录都必须可用）

```bash
# 方式一：从仓库根
pip install -r C题代码/code/requirements.txt
python C题代码/code/run_all.py
python C题代码/code/audit.py check-paper

# 方式二：从工作区
cd C题代码
pip install -r code/requirements.txt
python code/run_all.py
```

两种方式都能跑通，是第 3 节"禁止 CWD 裸路径"的直接后果——**不要把任何一种写死进代码**。

## 7. 与论文的接口

| 接口 | 约定 |
|---|---|
| 附录源程序 | `论文/code` 为软链接 → `../C题代码/code`；`\codefile{xxx.py}` 因此始终引入真实文件，**单一真源、零漂移** |
| 附录 E 清单 | 必须与 `code/` 下实际文件**逐字一致**（第 4 节的 24 个）；新增脚本必须同步补进 `论文/sections/90_appendix.tex` |
| 附录 A 文件树 | 与 `support.zip` 实际内容逐项对应 |
| 图片 | `论文/figures/` 只放 TikZ 源（fig01/fig02）与最终选用图；生成脚本在 `code/` |
| 合规自查 | `论文/tools/check_paper.py` 逐个核对 `论文/code/` 下的文件是否存在（经软链接即核对本工作区） |

## 9. 禁止事项（提交前自查）

1. 在 `C题代码/` 之外新建任何 `.py`（唯一例外见 §2.1 的 `_坑点复现/`）；
2. 出现 `TODO`/空壳函数——附录原样引入真实文件，空壳会被评审看到；
3. 脚本里出现依赖 CWD 的裸路径；
4. 改名后不同步 `论文/sections/90_appendix.tex`（附录会显示红色【缺文件】，`check_paper.py` 判失败，格式规范第五条红线）；
5. 任何位置出现学校、队号、姓名、赛区信息（含代码注释与文件头）。
