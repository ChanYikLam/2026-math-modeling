# 07 验证执行清单与团队分工

> 本文件把验证方案变成可排期的任务清单。建议队伍指定一名"验证负责人"（不写主要建模代码），
> 负责审计、泄漏测试与门禁放行。

---

## 1. 角色分工（3 人队）

| 角色 | 职责 | 验证相关 |
|---|---|---|
| A 建模/求解 | 数据预处理、模型、求解 | 提供模型元数据与结果文件 |
| B 审计/验证 | 独立审计脚本、泄漏测试、交叉求解器 | 不共用 A 的费用/约束函数 |
| C 统计/写作 | 场景、统计检验、图表、论文 | 配对设计、CI、样本外 |

> 若只有 2 人：B 的代码由 A 复核逻辑，但费用/平衡函数必须重写一遍。

---

## 2. 时间线（建议）

| 阶段 | 任务 | 产出 |
|---|---|---|
| 阶段 0（读题后） | 建立符号表、口径表、验证指标与阈值 | 本方案 + 假设清单 |
| 阶段 1 | Q1 LP + L1 特例 + L3 审计 | `result1.xlsx` + 审计通过 |
| 阶段 2 | Q2 两阶段 + 信息结构对照 + 报童对拍 | `result2.xlsx` + R1/R2/R3 对照 |
| 阶段 3 | Q3 滚动 + 泄漏测试 + VoI 三组 | `result3.xlsx` + VoI 曲线 |
| 阶段 4 | Q4 F1/F2/F3 + 风险前沿 | `result4-2/4-3.xlsx` + CVaR 前沿 |
| 阶段 5 | L4 消融 + L5 统计与灵敏度 + 样本外 | 验证章节初稿 |
| 阶段 6 | 全链路复现 + 结果文件回读 + 自查 | 提交包 |

## 5. 常见排期风险

| 风险 | 后果 | 应对 |
|---|---|---|
| 最后一天才想起验证 | 无时间修复 | 每问完成即跑门禁 |
| 验证与建模同一人 | 自证 | 交换复核或重写费用函数 |
| 只验证一个场景 | 尾部风险未知 | 多种子 + 尾部指标 |
| 结果文件最后才写 | 格式错、行数错 | 每问完成后立即导出并回读 |
| 忽视问题 3 的泄漏 | 结论被质疑致命 | 阶段 3 必做泄漏测试 |
| 把参考 Oracle 当自己的结果 | 学术不端风险 | 必须自行复现并记录版本 |
